# Регистрация и доступы: автоматическая проверка

Основной сценарий нового аккаунта: администратор нажимает «Создать компанию»
в настройках виджета, затем входит в TeamOS под собственной учётной записью.
Другой администратор того же amoCRM аккаунта получает собственную роль admin
в той же компании. Пароль и постоянная ссылка администратора в этом сценарии
не создаются. Контракт — [ADR-012](../adr/ADR-012-amo-widget-company-entry.md).

Администратор создаёт сотрудника с обычной ролью и выдаёт ему личную многоразовую
ссылку. Сотрудник получает только выданные разделы. Отзыв ссылки блокирует новые
входы по ней и обновление связанных сессий. Отключение пользователя также запрещает
новый вход и refresh. Уже выпущенный access JWT действует до своего короткого TTL;
проверки ниже не доказывают мгновенный отзыв JWT во всех доменных сервисах.

Регистрация по серверному registration-token и парольный вход проверяются как
существующие сценарии совместимости. Они не являются шагами нового входа из виджета.
Регистрация без такого токена создаёт отдельную компанию без связи с amoCRM.

## Запуск в изолированном окружении

Нужны Go из `go.mod`, Python 3 и доступный Docker для PostgreSQL testcontainers.
Запуск не обращается к развёрнутым сервисам: создаёт временные базы с миграциями
и фикстуры, удаляет контейнеры после тестов. Production `.env` и данные аккаунтов
не требуются; работающие сервисы не запускаются и не обновляются.

```sh
make test-account-access
```

Для Colima, если testcontainers не определяет сокет автоматически:

```sh
DOCKER_HOST=unix://$HOME/.colima/default/docker.sock \
TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock \
python3 scripts/test-account-access.py --log-dir /tmp/account-access-results
```

Без доступа к Docker можно выполнить только unit/API фикстуры:

```sh
make test-account-access-unit
```

Этот режим явно выводит `PostgreSQL acceptance NOT RUN`. Не считайте его полным
прохождением задачи. Runner проверяет обязательные имена тестов, запрещает skip
в выбранной матрице и возвращает ненулевой код при отсутствии нужного теста.
`--log-dir` сохраняет JSONL результатов; не прикладывайте реальные credentials.

## Что проверяется автоматически

| Область | Проверка |
| --- | --- |
| Регистрация | Владелец, точная amoCRM привязка, повторный/просроченный/отозванный/неизвестный токен, конкуренция двух реплик: один результат |
| Атомарность | Отклонённая регистрация не меняет компании, пользователей, credentials, ссылки, сессии и outbox; новая самостоятельная компания не меняет существующую |
| Администраторы | Одна компания, разные учётные записи, сохранение владельца, отсутствие неявного пароля и access-link |
| Сотрудник | JWT с правильными user/company/employee и только выданными разделами; нет управления чужим доступом; ссылка многоразовая |
| Сессии | Refresh, повтор потерянного ответа, конкуренция, logout только своей семьи сессий |
| Отзыв | Старая ссылка и refresh отвергаются, новая выданная ссылка работает; отключение сотрудника не отзывает доступ администратора |
| HTTP | Контракт, refresh-cookie, служебная авторизация и отказ старого browser entry через настоящие HTTP-маршруты с RPC-фикстурами |

CI job `Company account access acceptance` запускает эту PostgreSQL-матрицу
через `--integration-only`; штатные unit jobs проверяют HTTP-фикстуры. Runner
объединяет новые тесты с существующими регрессиями. Это не живая приёмка amoCRM и не проверка всего UI.

## Ручная приёмка — пользователю

После развёртывания проверенной версии установите виджет в отдельный тестовый
аккаунт и пройдите создание/повторный вход двумя администраторами. Затем выдайте
сотруднику ссылку, проверьте доступные разделы, повторный вход и отзыв ссылки;
проверьте отключение пользователя. Не меняйте доступ существующих компаний.
Фактический OAuth, права администратора amoCRM, callback, HTTPS/cookie, origin
и применённая версия nginx проверяются здесь вручную.

Доступ к Docker на Devcorps может ограничивать контейнерную часть: это отдельная
блокировка окружения. Локальный PostgreSQL-прогон фиксируйте отдельно от Devcorps.
Новый сервер rakurs-135 и его приёмка в эту проверку не входят.
