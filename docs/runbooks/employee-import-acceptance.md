# Проверить импорт сотрудников

Запускайте автоматические проверки на изолированной машине с Go 1.26.10 и Docker.
Они используют HTTP-фикстуры и временные PostgreSQL-контейнеры. Они не обращаются
к развёрнутым сервисам, amoCRM или `ssd.rkrs.ru`.

```sh
python3 scripts/test-account-access.py --log-dir /tmp/teamos-account-acceptance
```

Для проверки источника и выбранных PostgreSQL-сценариев без остальных unit-тестов выполните команду.

```sh
python3 scripts/test-account-access.py --integration-only --log-dir /tmp/teamos-import-acceptance
```

Runner завершает работу с ошибкой, если обязательный тест отсутствует, пропущен или упал.
Вариант `--unit-only` проверяет HTTP-клиент и unit/API-сценарии, но не доказывает работу PostgreSQL.
CI выполняет тот же вариант `--integration-only` в задании Company account access acceptance.

## Автоматически проверяемые сценарии

HTTP-клиент принимает ровно один JSON размером не более 4 МиБ, включая пробельные символы.
Неизвестные поля совместимы с текущим контрактом. Ошибки HTTP, бизнес-отказ,
отсутствующий массив, оборванный ответ, превышение лимита, таймаут и отмена запроса возвращают ошибку.
Успешный пустой массив остаётся полноценным пустым снимком.

Тесты `TestAmoImportHTTPToPostgres` и `TestAmoImportHTTPFailuresPreservePostgres` используют
настоящий HTTP-клиент и `ListUsers`. Они проверяют следующие результаты.

- Сотрудники и отделы создаются в компании, связанной с запрошенным аккаунтом.
- Повтор сохраняет UUID сотрудников, UUID отделов и связи с внешними пользователями без повторных событий.
- Одинаковые внешние ID и email разных компаний не смешиваются.
- Изменения групп обновляют отделы, сохраняя локальные имя, роль и неактивный статус сотрудника.
- Импорт создаёт обычных сотрудников без пароля, ссылки входа, сессии или доказательства административных прав.
- Отклонённые ответы не меняют сотрудников, связи, доступы, сессии, распределение и outbox.

Выбранная PostgreSQL-матрица также включает существующие проверки отделов, удаления,
восстановления и происхождения связей. Историческое совпадение ID или email не создаёт
новую подтверждённую связь с другим аккаунтом.

## Настройки источника

Сервис company использует `EXTERNAL_API_URL`, `APP_NAME`, `EXTERNAL_API_TIMEOUT`,
`COMPANY_AMO_IMPORT_ENABLED` и `COMPANY_AMO_SYNC_INTERVAL`.
По умолчанию источник имеет адрес `https://ssd.rkrs.ru/api/v1/rkrs_activity/getEmployee`,
приложение называется `rkrs_activity`, таймаут составляет 10 секунд.
Base Compose передаёт переключатель импорта с отключённым значением по умолчанию.
Production override устанавливает его в `true`, независимо от значения в `.env`.

Источник получает POST с `amo_account_id` из сохранённой компании и серверным `app_name`.
Текущий ответ содержит `result`, `message` и `data`. Каждая запись содержит строковый `id`,
`name`, необязательные `email`, `avatar` и `group` со строковыми `id` и `name`.
Отделы без сотрудников этот формат не представляет.

Импорт запускается при чтении списка сотрудников. Интервал ограничивает попытки,
включая ошибки, отдельно по компании внутри процесса. Это не фоновое расписание.
При ошибке источника чтение возвращает сохранённых сотрудников. Успешный ответ `ListUsers`
сам по себе не подтверждает успешный импорт.

## Условия ручной приёмки

До живой приёмки владелец источника должен подтвердить поддержку нового аккаунта для
выбранного `APP_NAME`, полноту снимка, ограничения размера, правила пагинации и смысл
неактивных сотрудников. Текущий контракт не содержит признака полноты, курсора,
статуса активности или подтверждения аккаунта в ответе. Фикстуры этого не доказывают.
Новый источник или пагинация требуют отдельного согласованного контракта.

Отсутствие ранее импортированного сотрудника в успешном снимке скрывает его,
отзывает сессии, удаляет пароль и ссылку входа, отключает распределение.
Возвращение сотрудника не восстанавливает удалённые средства входа.
Поэтому частичный успешный список опасен даже при корректном JSON.
Импорт не служит доказательством личности или административных прав.

Ручная приёмка аккаунта и развёртывание остаются за пользователем.
Проверка Devcorps для этой задачи обнаружила развёрнутый коммит `0ebe7db`, отличный от
проверяемой версии. Доступный MCP не показывает окружение контейнера, а пользователь
codex не имеет доступа к Docker для PostgreSQL-тестов. Изолированный unit-прогон
на Devcorps не заменяет проверку опубликованной версии и живого источника.
