# Подключить Activity к компании TeamOS

Эта настройка делегирует управление Activity текущим владельцам и администраторам компании TeamOS. Оператор проверяет компанию, аккаунт amoCRM и установку перед добавлением записи. Она не выдаёт пользователю TeamOS личность администратора amoCRM.

1. Убедитесь, что нужная установка Core активна, интеграция активна, сервис `activity` и пилот включены. В Activity задайте `ACTIVITY_APP_PUBLIC_ORIGIN` для выдачи действительных ссылок просмотра.
2. Сверьте UUID установки, UUID интеграции и `account_id` в Core. Аккаунт должен принадлежать активной проверенной интеграции `rakurs` выбранной компании TeamOS.
3. Настройте сервер `company` через секреты окружения.

```dotenv
COMPANY_ACTIVITY_CORE_URL=https://core.example.invalid
COMPANY_ACTIVITY_MANAGEMENT_TOKEN=<ACTIVITY_MANAGEMENT_TOKEN из Core>
COMPANY_ACTIVITY_BINDINGS=[{"companyId":"11111111-1111-4111-8111-111111111111","installationId":"22222222-2222-4222-8222-222222222222","integrationId":"33333333-3333-4333-8333-333333333333","accountId":"123"}]
```

4. Перезапустите `company` по обычной процедуре выпуска. Один аккаунт компании получает одну установку Activity. Повтор компании или установки в списке отклоняется при запуске.
5. Войдите в TeamOS владельцем или администратором. Откройте `/activity-control` и сверьте показанный аккаунт и установку.
6. Создайте панель, выберите сотрудников amoCRM и сохраните. Полученную ссылку сохраните отдельно. Откройте её и проверьте настройки в виджете amoCRM.

Настройки панелей, пороги звонков, планы, воронки и панель задач сохраняются только через API Activity в Core. TeamOS не хранит их копию. Панель задач Activity не является правилами продукта «Контроль задач».

Каждый запрос перечитывает активность компании, пользователя, его роль и принадлежность аккаунта. Каждый запрос настроек передаёт `X-Activity-Binding-Id`, полученный при чтении подключения. Изменение настроенной области возвращает 409 до обращения к Core. Заголовок служит ожиданием клиента, а не правом доступа. ID аккаунта в текущем профиле компании должен совпадать с настроенным ID и активной проверенной интеграцией. Изменение или очистка ID в профиле прекращает доступ к прежнему подключению. Core проверяет действующую установку, интеграцию, сервис и пилот. Заголовок `X-Activity-Account-Id` проверяет аккаунт на каждом операторском вызове. Ошибки источника не превращаются в пустые результаты или вызовы SSD. Адрес Core, токен и заголовки области доступа недоступны браузеру.

Удалите запись из `COMPANY_ACTIVITY_BINDINGS` и перезапустите `company`, чтобы отозвать делегирование. Отключение пилота или сервиса в Core действует на следующий запрос. Делегирование оператора сохраняется после повторной авторизации той же установки. Отдельной версии жизненного цикла установки в этом MVP нет.

Ссылки просмотра являются самостоятельными правами доступа. Отзыв роли TeamOS прекращает управление, но не отзывает уже выданную ссылку. Для отзыва ссылки отключите панель или явно замените ссылку. Обычное открытие панели не заменяет ссылку. При потере ответа создания или замены интерфейс повторяет ту же команду, пока окно не закрыто. Не повторяйте такую операцию из другого окна без проверки результата.

Конфликт версии сохраняет черновик. Закройте его после копирования нужных изменений, обновите страницу и откройте актуальные настройки. При недоступности источника сохранение не подтверждается. Telegram недоступен. Старый SSD доступен только по явно обозначенному `/legacy/ssd-activity` и хранит отдельные настройки.

Проверки для разработки находятся в `activitybridge/client_test.go`, `application/activity_control_test.go` и `application/activity_control_integration_test.go`. Последняя использует изолированный PostgreSQL через Testcontainers. При Colima задайте `DOCKER_HOST` из `docker context inspect` и `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock`. REST, DTO и protobuf обновляются командой `make gen`. Фронтенд генерирует типы из этого `contracts/openapi/teamos.yaml`.
